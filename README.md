## 🔬 颜色检测原理

```
屏幕坐标 (X, Y)
      │
      ▼
PixelGetColor → 0xRRGGBB
      │
      ▼
FormatColor → 6位十六进制 "RRGGBB"
      │
      ▼
               ┌─ variation=0 → 精确比较
ColorMatches ──┤
               └─ variation>0 → RGB逐分量差 ≤ variation
                     │
                     ▼
               │R屏 - R目│ ≤ V  AND
               │G屏 - G目│ ≤ V  AND
               │B屏 - B目│ ≤ V
```

| 函数 | 用途 |
|------|------|
| `GetPixelColor(x, y)` | 读取屏幕指定坐标像素颜色值 |
| `ColorMatches(x, y, target, var)` | 比较颜色是否匹配(含色差) |
| `HexStrToInt(hex)` | 十六进制字符串转整数 |
| `HexCharToInt(ch)` | 单字符十六进制转数字 |
| `FormatColor(raw)` | 统一颜色格式为6位大写十六进制 |

## 🔄 主循环执行策略

### 顺序轮询模式

```
         触发器A ──→ 触发器B ──→ 触发器C ──→ ...
           ↑                              │
           └──────────────────────────────┘

每 tick (50ms):
  1. 检查 currentTrigger (从A开始)
  2. 条件满足? → PressKey + 进入冷却
  3. 前进到下一个触发器 (A→B→C→A→...)
  4. 如果当前触发在冷却中 → 直接跳到下一个
```

### 冷却控制

```
触发成功 → waitUntilTick = now + minInterval
               │
          ┌────┘
          ▼
    MainLoop 每 tick 检查:
    if (currentTick < waitUntilTick)
        → 跳过本轮检查 → 不进到下个触发器
    else
        → 恢复正常轮询

目的: 防止同一触发器在冷却期内反复触发
```

## 🔧 技术细节

| 特性 | 实现方式 |
|------|----------|
| 🎯 颜色检测 | `PixelGetColor` RGB 模式 + 自定义逐分量比较 |
| ⏱ 循环定时 | `SetTimer` 定时器 (最小 10ms, 最大 1000ms) |
| 🪟 GUI 系统 | 原生 AHK Gui 控件 (Tab / ListView / Hotkey) |
| 💾 持久化 | `IniRead` / `IniWrite` 读写 config.ini |
| ⌨️ 按键模拟 | `SendInput` 带修饰符自动解析 |
| 🔌 热键 | 动态 `Hotkey` 命令注册，支持冲突检测 |
| 🧵 常驻 | `#Persistent` + `OnExit` 退出自动保存 |
